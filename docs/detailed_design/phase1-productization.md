## 1. 本パッケージの位置づけと進め方

[[../basic_design/15_development_process.md#4.1]] の実施順 9 と [[../basic_design/15_development_process.md#4.1.2]]、基本設計 13 章 B37 を受ける。作業パッケージをまたぐ開発の進め方は [[web-core-foundation.md#15]] に置き、本書は本パッケージに固有のことだけを書く。

- 本パッケージは、Phase 1 の実施順 9「Phase 1 完成・製品化」として、横断のパッケージ（XL のサイズ相当）で実施し、作業パッケージ 1 から 8 のすべてに依存する。 <!-- req 15:ce8dbfb4.3c06 --> <!-- req 15:ce8dbfb4.2364 -->
- 本パッケージでするのは、設計の横断の整合の是正、G1 の解消、画面とビジュアルの設計を製品の水準にすること（D1・D2）、全部の結線の実装と見た目の実装（I1・I2）、実際の UI を通した確かめ（F）とする。基本設計 15 章 4.1.2 節の追い込みの事項は、本パッケージに集める。本パッケージの詳細設計書は本書（作り直す前の本書は `2759936` 時点の `phase1-productization.md`）とする。 <!-- req 15:ce8dbfb4.6039 --> <!-- req 15:ce8dbfb4.1f2a --> <!-- req 15:ce8dbfb4.d83a --> <!-- req 15:ce8dbfb4.6250 --> <!-- req 15:ce8dbfb4.e16c --> <!-- req 15:ce8dbfb4.51d7 --> <!-- req 15:ce8dbfb4.4a27 --> <!-- req 15:ce8dbfb4.7053 -->
- 進める順は、設計（D1・D2）、実装（I1・I2）、実機での確かめ（F）の順とする。実装は、機能の結線（I1）を先にし、見た目（I2）を後にする。
- サブ機能（D1・D2・I1・I2・F）ごとに、ゴールと品質のゲートを置く。サブ機能に着手する前に、達成した状態・確かめる手段（できるだけコマンド）・範囲の外・同じ崩れ方を防ぐ手段の 4 つを決めてから始める。
- 品質の基準は `.claude/rules/core.md` に書き、設計書の相互参照の確かめ（`pnpm check:docs`）と UI の配線のダミーのハンドラの見つけ出し（`pnpm check:stubs`）を CI の品質のゲート（`pnpm run check:quality`、[[web-core-foundation.md#14]] の 14.7 節）につないで、作業パッケージ 1 から 8 のマージの後に見つかった崩れ方を機械で見つける。
- 基本設計 03 章（画面と UI）を、製品の水準に仕上げることを本パッケージに含める（D2 の設計、I2 の実装）。

### 1.2 Phase 1 の完了

- Phase 1（PC 版の MVP）の実装の段は、作業パッケージ 1 から 8 のマージに加えて、実施順 9 の本パッケージが完了の基準を満たした時点で完了とする。この 2 つがそろうまで完了としない。Phase 1 の完了は、Phase 2 に着手する前提とする。 <!-- req 15:0216ab75.b8af --> <!-- req 15:0216ab75.3514 --> <!-- req 15:0216ab75.2c79 --> <!-- req 15:0216ab75.7818 -->
- 本パッケージの完了の判定は、[[web-core-foundation.md#15]] の 15.7 節の 6 つの基準に加えて、次の表のすべてを満たしたときとする。本パッケージは Phase 1 の完了の定義を兼ねるため。 <!-- req 15:b065e033.096a -->

| # | 判定の条件 | 確かめ方 |
|---|---|---|
| 1 | 自動のゲートが通る | `pnpm typecheck`・`pnpm lint`・`pnpm test`・`pnpm build`・`pnpm format` |
| 2 | 品質のゲートが通る | `pnpm run check:quality`（`check:docs`・`check:stubs`・`check:test-ids` の見つけたものが 0 件） |
| 3 | D1 と D2 のゴールを達し、設計の横断の整合が回復している | 設計の横断の監査（`/audit design`）をもう一度回して、新しい Blocking と Major が 0 件 |
| 4 | I1 と I2 のゴールを達し、実装が詳細設計の全部の結線を持つ | 実装と設計の監査（`/audit impl`）の未結線の一覧が空 |
| 5 | 実際の UI の通しの確かめ（F）が済んでいる | G23 の P1 から P7 が全部の行で合格（本人が実際のアプリでする） |
| 6 | 未解消のギャップを、責任なく繰り越していない | [[00_reference.md#8.1]] の未解消の行のそれぞれに、解消を担う作業の単位と判定の条件が書いてある |
| 7 | 是正ごとに、同じ崩れ方を防ぐ手段が入っている | 1 節のサブ機能ごとの「同じ崩れ方を防ぐ手段」がすべて入っているか、入れられない理由が書いてある |

- (b) 作り直す前の本書 8 節の判定の条件を引き継ぎ、今は無い道具の名前（`sdlc-design-review`・`sdlc-impl-review`・`/audit-consistency`・`/audit-fidelity`）を、今ある横断の監査のコマンド（`.claude/commands/audit.md` の `design` と `impl`）に置き換えた。条件を判定できる形のまま残すため。
