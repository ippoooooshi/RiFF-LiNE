# phase-gate スキル

## 目的

承認済みフェーズ・作業パッケージの範囲を超えた作業を未然に防ぎ、フェーズ／作業パッケージ境界での同期更新（文書同時改訂・DoD）を漏れなく実施する。

## フェーズ定義の取得順序

1. `.claude/settings.meta.json` の `workflow.phases`（配列。`{ id, name, summary }`）を最優先で使う
2. 無ければ [`docs/basic_design/15_development_process.md`](../../../docs/basic_design/15_development_process.md) §4.1 / §4.1.1 の実施順序表を使う

現在どの作業パッケージまで完了しているかは [`docs/basic_design/00_overview.md`](../../../docs/basic_design/00_overview.md) の進捗ログで確認する。

## 起動手順

1. 上記の順序で現在の承認済みフェーズ・進行中の作業パッケージを特定する
2. 依頼内容を、承認済みフェーズ・実施順序（§4.1）・現在の進捗と照合する
3. 範囲判定
   - **範囲内**（現在の作業パッケージ、または依存関係の薄い小粒な作業〈§4.2 末尾〉）: そのまま実行へ進む
   - **超過**（実施順序上まだ前提パッケージが未完 / 承認済みフェーズを超える / 要件変更を含む）: 以下の確認文を提示し、明示承認を得るまで着手しない
     ```
     ご依頼は現在の承認済み範囲（Phase<番号>: <名称> / 作業パッケージ<番号>: <名称>）を超える可能性があります。
     - 超過分: <作業概要>
     - 想定フェーズ／パッケージ: <番号・名称>
     - 実施順序上の前提: <未完の前提パッケージがあればそれ>
     このまま進めてよろしいですか？（はい / いいえ / 範囲を縮小して進める）
     ```

## 作業パッケージ完了時の同期更新チェックリスト

- [ ] 詳細設計書（`docs/detailed_design/<スラッグ>.md`）が実装と整合している（DoD 基準2）
- [ ] `docs/detailed_design/00_reference.md` の §3（クラス登録簿）・§4（拡張履歴）・§5（エラーコード表）・§6（依存グラフ）・§8.1（既知ギャップの解消／持ち越し記録）
- [ ] `docs/basic_design/00_overview.md` の進捗ログ
- [ ] `docs/basic_design/13_design_decision_points.md`（新規分岐点があれば）
- [ ] 例示リスト（`docs/basic_design/08_error_logging.md` §1 等）への新規エラーコード反映（G20 の教訓）
- [ ] `.claude/docs/structure.md`（ファイル・モジュールの増減があれば）
- [ ] テスト（DoD 基準3: 全メソッド C0/C1 100%、対象ロジック C2、結合テスト）
- [ ] セルフレビュー実施済み（DoD 基準4、サイズ問わず全件対象）
- [ ] 手動シナリオ確認 最低1件（DoD 基準5）
- [ ] 機微情報の混入がないこと
- [ ] **パッケージ固有のゲート文書がある場合はそれも満たす**（例: 「Phase 1 完成・製品化」は [`.claude/docs/phase1-productization.md`](../../docs/phase1-productization.md) の設計ゴール G-D / 実装ゴール G-I。サブ機能境界〈D1/D2/I1/I2/F〉ごとに該当ゲートを確認）

## アンチパターン

- 「軽微だから」「すぐ戻せるから」を理由に超過着手する（§0.1 の是正の趣旨に反する）
- 完了報告のみで文書同時改訂・DoD を省略する
- 一時ファイルをプロジェクト規約外のパスに作成する（scratchpad を使う）
