# 設計

`docs/` 配下の設計ドキュメントだけを書く。`packages/**` `apps/**` には**一切触れない**（PreToolUse が拒否する）。

## 0. 書く前に、分母を固定する

**これを飛ばさない。** 設計を書く作業は「上位が要求していることを下位へ降ろす」ブレイクダウンで、
降ろし漏れは**書いている最中には見えない**（書いた側は全部やったつもりになる）。
上位が何件を要求しているかを先に機械へ固定させ、それを分母にして書く。

この作業の担当段は `node .claude/scripts/state.mjs show` の `ledger`（`edge` と範囲）。

```bash
node .claude/scripts/ledger.mjs pending "<edge>" --file "<範囲>"
```

**未分解が 1 件でも残っていたら、先に分解する。**

```bash
node .claude/scripts/ledger.mjs next "<edge>" --phase decompose --file "<範囲>"
# 1 件ずつ show して、上位の原文だけを見て要求を列挙し、decompose で書き戻す
#   要求には原文の逐語の出どころ（from）を添える。要求でない部分は理由つきで skip する。
#   同じ部分を 2 つの項目が指すことはできない（言い換えでの件数合わせが落ちる）。
#   何も要求していない行は、原文全体を 1 つの skip にする（要求ゼロとして記録される）。
#   書式は /trace の `phase: "decompose"` 節を見ること
```

分解のとき **下位のドキュメントを開かない。** 下位を見ながら列挙すると、
下位に無いものが列挙から漏れる——見落としているものは原理的に列挙に上がらない。
これで過去に 25 件見落とした。分解の件数が機械の推定下限を下回ると拒否される。
**下限を満たすために要求を水増ししない。** 原文が本当に下限に満たないなら、
拒否されたことをそのまま報告する（下限推定の誤検出として扱う）。

未分解 0 になってから書き始める。未分解が残ったまま `docs/` を編集したターンは Stop hook が終わらせない。

## 先に読む

- `.claude/project.json` の `paths` / `tiers` / `idPrefixes`
- 対象の `docs/detailed_design/<スラッグ>.md`（既存なら）と、対応する `docs/basic_design/*`
- `docs/detailed_design/00_reference.md` §3（他パッケージの現行シグネチャ）・§8.1（既知ギャップ。**着手対象に関連する未解消ギャップを必ず確認**）
- `docs/basic_design/13_design_decision_points.md` の関連分岐点

## 完了条件は「実装が迷わない粒度」

責務の散文で止めない。**クラス／インターフェース一覧と責務、主要メソッドのシグネチャ（引数・返り値・例外時の挙動）、状態遷移、シーケンス**まで確定させる。

曖昧なまま実装に渡すと、実装が勝手に決めて設計と乖離し、乖離が検出されないまま積み上がる。過去に WP4〜8 の5パッケージがこれで積み上がった（G1）。

新規クラスには**スコープ**（編集ウィンドウ単位／アプリ全体／ステートレス）を明記する。

## 同じターンで連動更新する

`.claude/rules/docs.md` の表に従う。特に：

- `00_reference.md` §3（クラス登録簿）／§4（非破壊拡張履歴）／§5（エラーコード統合表。新規コードがあれば `08_error_logging.md` §1 の例示リストも同ターン）／§6（依存グラフ）
- `00_overview.md` の進捗ログ
- `13_design_decision_points.md`（新たに確定した分岐点があれば。カテゴリB＝工学判断／C＝ヒアリング確定を区別）
- 基本設計側の記載を変える必要が生じたら、**先に**分岐点として記録してから基本設計を更新し、それから詳細設計を確定する

## クロスリファレンスを書いたら、その場で開く

`[[相対パス#見出し]]` を書いた**直後に**その節を読み返し、該当内容が実在するか確認する。確認せずに「反映済み」と書かない。

作業終了前に `node .claude/scripts/check-docs-links.mjs` を実行し、0 件を確認する。

## 止まる条件

以下に当たったら、**推測で埋めずに停止して報告する**。質問の書式は `.claude/rules/core.md` §2。

- **上位文書が矛盾している** — 両論を逐語引用し、どちらを採るかを本人に決めてもらう。黙って一方を採らない（G46 の再発防止）
- **決めるべき中身が未定義** — 名前や置き場所はあるが何をするかが書かれていない（「等」「など」で列挙が閉じていない箇所を含む）
- **ID が衝突した** — `REQ-` / `UT-` / `IT-` / `G##` の新規採番が既存と衝突したら、採番を確定する前に停止して報告する
- **スコープを超える** — 承認済みフェーズ・作業パッケージの範囲外

## 書き終えたら、分母の全件を判定する

書いた時点では「漏らしていないつもり」でしかない。固定した分母の 1 件ずつを、
**実際に書いた下位文書と突き合わせて**判定する。

```bash
node .claude/scripts/ledger.mjs next "<edge>" --phase judge --file "<範囲>"
node .claude/scripts/ledger.mjs judge "<edge>" "<reqId>" <判定> '<evidence JSON>'
```

- 判定は下位を**実際に開いて読んで**行う。目次や「〜に反映済み」という記述を根拠にしない
- `一致` 以外（`部分` `不一致` `申し送り先が不在` …）が出たら、**それは自分の書き漏らし**。
  書き足してから判定し直す。「部分」のまま次へ進まない
- evidence の `quote` は逐語で **12 文字以上**、引用元は**下位の成果物**（上位文書や `.claude/` を引用しても記録されない）、行番号は ±3 行まで。
  **`一致` と `部分` は `method` だけでは記録できない**——「在る」ことの証拠は逐語引用にしかならない。
  「無い」ことを示す判定（`不一致` など）のときだけ、`method` に grep した語と結果件数を書く
- **未判定が残っている間は完了と報告しない**

## 出力

変更したファイル一覧、追加した ID、新規に確定した分岐点、そして**確認していない事項**（あれば）を明記する。「未確認」を書くことは失敗ではない。

あわせて台帳の実測を貼る（自己申告ではなく `pending` の出力をそのまま）。

```bash
node .claude/scripts/ledger.mjs pending "<edge>" --file "<範囲>"
```
