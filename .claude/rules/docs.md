# ドキュメント規約

> リンクの実在検証は `node .claude/scripts/check-docs-links.mjs` が行う。ここには**書き方**だけを置く。

## 参照記法（参照元と参照先の組み合わせで決まる）

| 参照元 → 参照先 | 記法 |
|---|---|
| `docs/` → `docs/` | Wikilink `[[相対パス#見出し]]`。パスは**参照元ファイルからの相対**で書く。同一ディレクトリのファイル名だけの参照は解決するので許容するが、どちらかを移動すると壊れるため新規では避ける（`check-docs-links` が助言として数える） |
| `docs/` → `.claude/` | Markdown 相対リンク。Wikilink は `docs/rules/` に解決してしまい常に壊れる |
| `.claude/` → 任意 | Markdown 相対リンク |

記法そのものを説明する場合、および壊れたリンクを引用する場合はバッククォートで囲む（コードスパン内はリンクとして解釈されない）。

## 文書同時改訂

1つの決定・修正を行うとき、関連する全ドキュメントを**同じターンで**更新する。片方だけ直すと、どちらが正か分からなくなる。

| 変更の種類 | 同時に更新する |
|---|---|
| コマンド／バリデーション仕様 | 該当基本設計 ＋ 該当詳細設計 ＋ `00_reference.md` §3 §5 |
| エラーコードの追加・変更 | 該当詳細設計 ＋ `00_reference.md` §5 ＋ `basic_design/08_error_logging.md` §1 の例示リスト |
| ディレクトリツリー・ファイル配置 | `basic_design/06_file_io_persistence.md` §3 ＋ `detailed_design/data-model-persistence.md`。**1ツリー行には1パスのみ**（カンマ区切り併記禁止） |
| 新規詳細設計書の作成、基盤インターフェースの非破壊拡張 | `basic_design/00_overview.md` ＋ `13_design_decision_points.md`（新規分岐点があれば）＋ `00_reference.md` §3 §4 §5 §6 |

## 同じ事実を2箇所に書かない

書く必要があるなら一方を「正」と明記し、他方はそこへの参照に留める。値・シグネチャ・上限値・エラーコードのレベルは、定義箇所を1つに決める。

## 決定と分岐点の記録

- 実装中に基本設計と異なる判断が必要になったら、まず `13_design_decision_points.md` に分岐点として追記してから該当設計書を更新する。順序を逆にしない。
- 詳細設計のシグネチャと実装が乖離したら、実装を設計に合わせるか設計を更新するかを**その場で**選ぶ。放置しない。
- §8.1 のギャップは、解消したら「解消済み（日付・対応パッケージ）」へ書き換える。**行を削除しない**（何が問題だったかの記録を残す）。

## 引用するとき

他の設計書のクラス・メソッド名を引用する際は、**引用元を実際に開いて現行シグネチャを確認してから**書く。`00_reference.md` §3 は一次参照先に使えるが古い可能性がある。疑わしいときは原典を見る。
