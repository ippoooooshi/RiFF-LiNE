# UI 規約【プロジェクト固有】

## 置き場所（基本設計 01 章 AD-5・13 章 B36、2026-09-26 本人決定）

| 書くもの | 置き場所 |
|---|---|
| 画面の部品（React、見た目） | `packages/ui-desktop` |
| 見た目に関係しない画面の処理（ViewModel など。iPhone 版でも使える） | `packages/core/src/ui` |
| レンダラーの起動と DI の組み立て | `apps/desktop/src/renderer`（**ここに画面の部品を置かない**） |

要件 6 章は「全画面UI は Webコア側に実装し、シェル側に画面を持たせない」と決めている。`apps/desktop` はシェル（Windows とのやりとり）なので、画面の部品をここに置くとこの決まりに反する（turn 76 の判定で「不一致」になった）。

## 完成とは、繋がっていること

シェル・スタブ・ダミーハンドラは**完成ではない**。完成とは、設計が定めた接続先（Service / Controller / IPC）へ実結線され、その経路が自動テストで検証されている状態。

```tsx
onRename={() => undefined}     // ← これは未完成。check-stubs.mjs が検出する
```

意図的に繰り越す場合のみ、`// quality-allow-stub: <理由と、いつどの作業単位で解消するか>` を書き、**同時に** `00_reference.md` §8.1 へ G 行を起こす。片方だけでは通らない。

> 15 画面が `() => undefined` のまま「シェル段階だから非ブロッキング」と分類され、実 UI で初めて破綻が露見した（G23）。この規約はその再発防止。

## 配色

配色は直接書かない。**テーマトークン経由**で参照する。ダークモードは現時点で不要だが、トークン化しておくことで後から追加できる状態を保つ（要件で明示）。

ビジュアルの正は `docs/basic_design/14_visual_design_system.md`。ここから外れた値をコンポーネント側で決めない。

## PC 版の操作慣習

要件 4.5/4.6 は **iPhone 版の仕様**であり、PC 版にそのまま適用しない。PC 版の正は `docs/basic_design/03_screens_ui_pc.md`。

- キーボードショートカットは OS 標準の慣習に従う（Ctrl+Z / Y、Ctrl+C / V）
- 右クリックのコンテキストメニューに対応する
- ウィンドウは最小 800×600、上限なし
- 高解像度ディスプレイは Electron 標準の挙動に任せる

## エラー表示の4段階

| レベル | 表示方式 |
|---|---|
| Info | 自動消滅する軽量トースト |
| Warning | やや目立つトースト＋アイコン（操作継続可） |
| Error | その場でブロック＋該当箇所を赤くハイライト（モーダルなし） |
| Critical | 確認必須のモーダルダイアログ |

**レベルは実際の挙動と一致させる。** 操作を拒否するなら Error 以上、継続を許すなら Warning 以下。ここがずれると、ユーザーは表示を信用しなくなる。

## 判定できないもの

見た目の良し悪し、操作感、音の確認は**本人が実アプリで判断する**。AI は「結線されているか」までを判定し、それより先は「未確認」と書く。
