# ドキュメント運用規約

> 権威: [`docs/basic_design/15_development_process.md`](../../docs/basic_design/15_development_process.md) §9、[`docs/detailed_design/00_reference.md`](../../docs/detailed_design/00_reference.md) §8（運用ルール）、ルート `CLAUDE.md` §4。

## 【最重要】文書同時改訂の原則

本プロジェクトの設計ドキュメント群は Wikilink 形式 `[[相対パス#見出し]]` で相互参照し合い、密結合している。
**1 つの決定・修正を行うとき、それに関連する全てのドキュメントを同じターン（同じパス）で更新する。**
片方だけ直して他を放置すると、`docs/review/` の監査で指摘される種類の不整合（過去実例 A-1〜A-5, B-1〜B-5, G1〜G21）が再発する。

### 典型的な連動例

| 変更の種類 | 同時に更新するファイル |
|---|---|
| コマンド／バリデーション仕様の変更 | `basic_design/04_editing_core.md` ＋ `detailed_design/editing-core.md` ＋ `detailed_design/00_reference.md`（§3 クラス登録簿・§5 エラーコード） |
| エラーコードの追加／変更 | 該当パッケージの `detailed_design/*.md` ＋ `detailed_design/00_reference.md` §5（統合表）＋ 例示リスト（`basic_design/08_error_logging.md` §1 の「発生源の例」列）も同ターンで（G20 の教訓） |
| ディレクトリツリー／ファイル配置の変更 | `basic_design/06_file_io_persistence.md` §3 ＋ `detailed_design/data-model-persistence.md`。**1 ディレクトリツリー行には 1 パスのみ**（カンマ区切り併記禁止、G21・B29 の教訓） |
| 新しい `detailed_design/*.md` の作成、または基盤インターフェースの非破壊拡張 | `basic_design/00_overview.md`（進捗ログ・索引表）＋ `basic_design/13_design_decision_points.md`（新規分岐点があれば）＋ `detailed_design/00_reference.md`（§3 登録簿・§4 拡張履歴・§5 エラーコード表・§6 依存グラフ）を**同じターンで**（§8 運用ルール） |
| リポジトリのモジュール／ファイルの増減 | `.claude/docs/structure.md` の該当行 |

## クロスリファレンスの検証

- 他パッケージの詳細設計書に登場するクラス・メソッド名を引用する際は、**引用元の詳細設計書を実際に読んで現行シグネチャを確認してから**引用する（G3 のような命名不一致の再発防止）。`00_reference.md` §3 は一次参照先に使えるが古い可能性があるため、疑わしい場合は原典を確認
- 「反映先」として節番号付きのクロスリファレンス（`[[file.md#N]]`）を書いたら、**記載直後に一度その節を読み返して**該当内容が実在するか確認する（G19 の教訓）
- ある詳細設計書が「別パッケージへの申し送り」を書いた場合、申し送り先の着手時に**実際に実装されたかを照合する**（G6 の教訓）

## 決定・分岐点の記録（§9、13番の運用ルール）

- 実装中に基本設計書の記載と異なる判断が必要になったら、まず `13_design_decision_points.md` に分岐点として追記してから該当設計書を更新する。基本設計書を実装後に古いまま放置しない
- 詳細設計書に定義したシグネチャ・構成と実装が乖離したら、実装を詳細設計に合わせるか、詳細設計書を更新するかを都度選び、乖離したまま放置しない（DoD 基準2）
- 8.1 節「既知のギャップ」は、解消したら該当項目を「解消済み（日付・対応パッケージ）」に書き換える。**削除はしない**（何が問題だったかの記録を残す）

## 既知ギャップの確認（着手前提）

作業パッケージに着手する前に、必ず `00_reference.md` §8.1（既知ギャップ G1〜）を確認し、着手するパッケージに関連する未解消ギャップが残っていないか確認する（`CLAUDE.md` §7）。

## 禁止事項

- 変更ログや作業記録を目的とした**新規 Markdown ファイルの作成**（既存ファイルを更新する）
- `docs/` フォルダ構成の変更（`[[相対パス#見出し]]` の相対リンクが壊れる）
- 機微情報（個人データ・認証情報・実ファイルのフルパス）の記載

## 体裁

- 見出しは `#` から階層的に。最上位は H1（1 ファイル 1 つ）
- 他ドキュメント参照は相対リンク（`docs/` 内文書間は Wikilink `[[相対パス#見出し]]`、`.claude/` 内は Markdown 相対リンク）
- コードブロックには言語識別子を付与
