# TypeScript 規約【プロジェクト固有】

> `tsc` / ESLint が判定できるものはここに書かない（`strict`、未使用変数、import 順など）。ここには**機械が判定できないもの**だけを置く。

## 単一の真実源

同じ値・同じ判定ロジックを2箇所に持たない。上限値・エラーコード・バリデーション閾値は定数として1箇所に定義し、他はそれを参照する。設計書に書かれた値をコード側でハードコードし直さない。

同種のロジックの二重定義を見つけたら、その場で片付ける。「後で統合する」は Q4 の台帳に載せるか、今やるかのどちらか。

## トレーサビリティ併記

振る舞いを担うコードには、対応する設計書の節番号と要件 ID／テスト ID を併記する。

```ts
/** 拍子変更コマンド。詳細設計 editing-core.md §5.3、REQ-4.1-METER、UT-EDIT-CMD-12 */
export class SetTimeSignatureCommand implements Command { … }
```

これが無いコードは、レビューで**トレーサビリティ断絶**としてブロッキング扱いになる。

## 型

- `any` を書かない。型が決まらないなら `unknown` で受けて絞る。
- 公開 API の引数・返り値・throw する例外は、詳細設計書に書かれたものと一致させる。乖離したら実装を設計に合わせるか設計を更新するかを**その場で**選ぶ。
- ドメインの識別子は素の `string` にしない（branded type かリテラル union）。

## 不要物

不要になったコードは**物理削除する**。コメントアウトして残さない。消したことは git が覚えている。

## エラー

- エラーコードは `00_reference.md` §5 の統合表に定義されたものだけを使う。新規追加は設計と同じターン。
- 例外メッセージ・ログに機微情報（個人データ・認証情報・実ファイルのフルパス）を含めない。
