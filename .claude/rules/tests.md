# テスト規約

> ID の付与・採番簿との整合と空振りの検出は `check-tests.mjs`、カバレッジは `check-coverage.mjs` が検査する。ここには**書き方**と、機械が見ない方針だけを置く。

## 命名と ID の書式

テスト名は `<対象>_<条件>_<期待結果>`。ID とプレフィックスは2か所に分けて書く。

```ts
// UT-PLAY-SVC: PlaybackService（再生・シーク・ループ・ソロ・preWarm）  ← ファイル先頭
// 検証節: playback-integration.md §4.6.2                            ← ファイル先頭
…
  it('PlaybackService_ループ終端_開始小節へ再シークする', () => {
    // UT-PLAY-SVC-07 §4.6.2「ループ境界の扱い」                      ← 各テスト
```

- プレフィックスは採番簿（`docs/basic_design/11_test_strategy.md` §3.1）で**予約されたものだけ**。新しい対象を足すときは実装と同じターンで採番簿に行を足す。
- 連番は同一ファイル内で 01 から。**既存の番号は再利用しない**（削除したテストの番号は欠番のまま残す）。番号が指す対象が入れ替わると過去の記録と照合できなくなる。
- ファイル内の全テストが同じ節を検証するなら、節番号はファイル先頭の1行で足りる。
- **連番まで各テストに書くのが原則**だが、書いていないテストは**ファイル先頭のプレフィックスを継ぐ**（網羅台帳はそれで段を判別する）。番号は継がない——採番簿に無い ID を機械が作ることはしない。
- **ファイル先頭に UT と IT のプレフィックスを両方書かない。** どちらのものか決められないテストは、どの段の分母にも入らず `node .claude/scripts/split.mjs orphan-tests` が赤にする。1 ファイルに両方が要るときは、各テストに連番つきの ID を書く。

## 何を検証するか

- **振る舞いを検証する。実装をなぞらない。** モックに設定した戻り値をそのまま assert するテストは、何も検証していない。
- 振る舞いを変えたのに旧仕様のままテストが通る状態（false positive）は不可。変更に対応する UT / IT を必ず同期する。
- 決定的に再現できないケースを無理に PASS させない。`it.skip` ＋ 理由コメントを明記して残す。

## UT 方針

- 外部ライブラリ（`@coderline/alphatab` 等）・I/O（fs・IPC）はモックまたは fake で差し替える
- 純粋ロジックを中心に検証する

## IT 方針

- OS の一時ディレクトリ（`os.tmpdir()` 配下）にテスト用フォルダを作り、テスト後に必ず破棄する
- ライフサイクル（初期化 → 操作 → クローズ）の通し動作を検証する
- IPC は fake `ipcMain` / `ipcRenderer` でハンドラを捕捉し、チャンネル契約どおりに委譲されることを確認する

## 禁止

- 本番データファイル・実ストレージルートの参照
- ネットワーク通信
- 機微情報を assertion メッセージ・ログに含めること
- テスト実行順への依存
- **テストを通すためにテストを書き換えること**（実装フェーズ中は PreToolUse が物理的に拒否する）
