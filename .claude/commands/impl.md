### 分け方の決まり（洗い出しの役の `rules` に逐語で渡す）

1. 前置き・理由・目的の句と、表の左列の見出し語は、skip にせず、支えている要求の with に入れる
2. 出典・参照、経緯・旧方針、段落の見出し・ラベル、枠組み・位置づけの文は、要求にしない。with に入れられないものは skip にして理由を書く

4. 「A と B の両方」「／」で並んだものは、項目ごとに分ける
5. コマンドの段の名前は必ず引用符で囲む（"bd-dd"）
6. 一時ファイルを含め、リポジトリの中にファイルを作らない
7. 範囲を閉じる文・提供しないと決める文・既定に任せると決める文は、2 の「枠組み・位置づけ」に入れず、要求として分ける

## 5. コマンドの決まり（量を減らす決まりを含む）

- `L` は `node .claude/scripts/ledger.mjs`。**段の名前は引用符で囲み `"dd-impl"`・`"bd-dd"`・`"req-bd"` の形**（`"bd->dd"` は `>` が向け先になる。台本の文字列の中でも同じ）
- **コマンドは本体も作業用の AI も 1 本ずつ打つ。** `cd` を打たない。`&&`・`;`・`|` でつながない。`git add` と `git commit` は別の Bash
- heredoc と `$( )` を使わない。`node -e`・`python -c` の文字列に文書の文を入れない（台本は Write で scratchpad に書いてから打つ）。`//` を含む引数には `MSYS_NO_PATHCONV=1`
- **出力を小さくする**：
  - `--json` は、数や ID を読み取る必要があるときだけ付ける。一覧の全部が要らないときは付けない（文字の出力は先頭の数件で切れている）
  - 同じファイルを何度も Read しない。**300 行より長いファイルは丸ごと読まない**（Grep -n で行を見つけて offset と limit で読む）。設計書の要求の文は `$L show` か `req-list` で取る
  - `.claude` の台本の中身を読まない（使い方は台本の先頭の注を Grep で引く）。前のターンの from-cc は to-cc が求めたときだけ読む
  - 出力が 30KB を超えると別のファイルに逃がされ、それを読み直すことになる。`--max` を小さくする・範囲を分けるなどして、1 本の出力を小さくする
  - 会話の大きさは `node .claude/scripts/context-report.mjs` で見られる（読むだけ）。区切りの切れ目で 1 回見て、本体の会話が 25 万を超えていたら、残りの仕事を作業用の AI に回す
  - 始まりと終わりの確かめは `turn-check.mjs` の 1 本にする（個々のコマンドを並べて打たない。赤が出たときだけ、そのコマンドを直に打って全文を見る）
  - ワークフローの結果は要るところだけ読む（`notOk` と数）
- ID を多く渡すとき（目安 30 件より多い）は、scratchpad のファイルに 1 行ずつ書いて `idsFile` で渡す
- コミット：件名は型から始め、型の後ろを小文字か日本語で始める（大文字の ID で始めると断られる）。100 文字以内。`git commit -q -F <scratchpad の文のファイル>`。commitlint の型は feat・fix・refactor・test・docs・chore だけ。**指示にあるまとまりだけをコミットする**。間違ったコミットは書き換えずに報告する（戻すのはチャット側の指示で `git revert`）
- コミットの直後に Bash で git を打たない（届いたかは `.git/refs/heads/<ブランチ>` を Read）。終わりの時刻は最後のまとまりのコミットの前に `date` で控える
- 行の数は Read の行番号で見る（`wc -l` は止められる）
- ワークフローはパスで回す（`scriptPath`）。名前で呼ばない
- **止められたら**：安全チェック・権限・見張りに止められたら打ち直さない（別の書き方・別の道具でも打たない）。止められた操作の全文と終わらなかった分を from-cc-detail.md に書いて、ほかへ進む。例外：理由が自動モードの安全チェックの一時的なエラーで、読むだけのコマンドなら 1 回だけ打ち直してよい。見張りが宣言で止めたら宣言をし直して進めてよい（全文を報告に）。1 本のコマンドが 10 分を超えて返らないときは全文と時刻を控えて報告に書く。作業用の AI が返ってこないときは `wf-tail` を見たうえで同じ設定で 2 回まで回し直してよい
- 打った書き込みの種類は控えておく（終わりの確かめの `--expect` に入れる：judge・plan・sync・decompose・stale-diff・approve・settle・reanchor・sibling-align・defer・approve-mechanical・hold など、打ったものだけ）
- リポジトリにフルパスを書かない。一時ファイルは scratchpad に書き、消さない

## 6. 終わりの確かめ（1 本）

```
node .claude/scripts/turn-check.mjs end --since <このターンの始まり> --expect <打った書き込みの種類をカンマで> --scope "<ファイル名>:<a-b>" [--scope …] --verify
```

- `--scope` は、そのターンに扱った区切りと、作業パッケージの区切り全部（照合前 0・印なし 0 を見る範囲）
- dd-it の段を扱ったターンは `--scope-edge "dd-impl" --scope-edge "dd-it"` を足す（既定は dd-impl だけ。v62）
- 見るもの：道具のずれ・drift・切り分けの覆いと表の疑い・check-config・文書のリンク・【要確認】・今日より後の日付・引用切れ（req-bd・bd-dd・dd-impl）・範囲ごとの未分解と照合前とダブルチェック前と印なし・分類（plan-report）・陳腐化の積み残し（4 段）・想定外の書き込み・一時ファイル・直下の新しい未追跡・check-tests・verify・報告の言葉
- **全部緑にしてから** `_bridge/` をコミットする。赤が残ったら、何が赤かと理由を報告に書く
- 加えて、文書を直したターンは、直した文書が to-cc の挙げた所だけか（行ごとに HEAD と比べ、消すつもりの無い行が消えていない）を確かめる
- テストを足したターンは、足したテストが効くこと（直したコードを一度外すと落ちること）を確かめる

## 7. 報告

- `_bridge/from-cc.md`：**25 行以内**、frontmatter に `answering: <turn>`。印の手順・始まりの確かめ・したこと・数（進捗管理ファイルから。前の報告の数を写さない）・照合の結果と内訳・plan の数・1 件あたりの量・終わりの確かめ・止められた回数と理由・本人の判断が要る点（honnin-queue の番号）・チャット側で決めてほしいこと
- `_bridge/from-cc-detail.md`：要るものだけ。部品ごとの扱い・先送りの一覧（受け持ちごとの数と例）・照合で一致しなかったものの一覧（plan の受け持ち先つき）・区切りの表の範囲・照合の回ごとの件数と AI の数とトークンと時間・時間の内訳（まとまりごとの始めと終わりの時刻と、そのうち作業用の AI が動いた時間）
- honnin-queue.md に積む形：上の表に 1 行（番号・所・何を決めるか・おすすめ案・積んだターン・「未」）と、本文に 1 節（一言で・何を決めるか・なぜ決まっていないか・原文・おすすめ案と根拠・反対する理由・選べる案・決めた後）。**本人が読む文なので平易な言葉で**。決まった番号は、決定を書いたターンの終わりに本文の節を `honnin-done.md` の末尾へ切り取って移し、表の行は「決定 <日付>（<要点>）→ honnin-done.md」だけ残す
- 終わりに `_bridge/` をコミットする（from-cc.md が 25 行以下を確かめてから。この報告・archive の to-cc 2 つ・honnin-queue・honnin-done・active-turn.md）
- **使った量を測る**（v62）：`_bridge/` をコミットする前に `node .claude/scripts/context-report.mjs`（読むだけ）を打ち、from-cc-detail.md の終わりに「呼び出しの回数・最後の会話の大きさ・読み直した量の合計・会話に足された量の上位 5」を写す
- **ターンの最後のメッセージは、チャット側へ貼るプロンプトをコードブロックで 1 つだけ出す。** 形は「turn <N> が終わりました。_bridge/from-cc.md と _bridge/from-cc-detail.md を読んで、turn <N+1> の指示（_bridge/to-cc.md と _bridge/to-cc-detail.md）を書いてください。」に、止まった点・終わったこと・残っていること・チャット側で決めてほしいこと・本人に聞くことの見出しを短く足す
