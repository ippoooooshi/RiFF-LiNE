# 本人に決めてもらう

引数: `$ARGUMENTS`（空なら `req->bd`）

分解でも承認でも決着しない断片が残ることがある。原因はたいてい**要件定義書側**で、
「アコースティックギター等」のように列挙が閉じていない。**これは分解のしかたの問題ではないので、
何度分解し直しても直らない。** 本人が決めるしかない。

このコマンドは**聞いて記録するところまで**。要件定義書の編集は別の指示でやる。

---

## やってはいけないこと（先に書く）

- **サブエージェントに委譲しない。** `AskUserQuestion` はサブエージェント内では使えない
  （出典: https://code.claude.com/docs/en/agent-sdk/user-input 「Subagents: AskUserQuestion is not
  currently available in subagents spawned via the Agent tool」）。委譲すると、聞けないまま
  **AI が勝手に答えを決める**方向へ落ちる。本スレッドで実行すること。
- **まとめて最後に記録しない。** 1 件答えが返ったらその場で `ask-record` する。
  実測でセッション制限に当たって途中で止まったことがある。**記録していない分は全部消える。**
- **選択肢を汎用にしない。** 「A) 列挙を閉じる B) 言い切る」はどの箇所にも貼れるので、
  押しても何も決まらない。**原文を読んで、具体的な中身の候補を出す。**
- **推測で埋めない。** ここに出ているのは、原文からは決められないと機械が判定した箇所。

---

## 1. 聞くことを取り出す

```bash
node .claude/scripts/ledger.mjs ask "<edge>" --json
```

`groups[]` が本人に聞く単位。**行ごとにまとまっている**（本人が直すのは行なので）。
一度答えたものは既定で出ない（`--all` で全件）。空なら終わり。

各 group の中身:

| 鍵 | 何か |
|---|---|
| `key` | 記録するときの鍵。**原文の本文ハッシュ**なので、原文を直すと消える |
| `header` | 質問ツールの見出し（12 文字以内に詰めてある）。**そのまま使う** |
| `source` | 原文。質問に**逐語で 12 文字以上**含めること（含めないと記録が拒否される） |
| `spans` | 止まっている断片 |
| `findings[].ask` | 機械が作った質問文。**何を聞くべきかはこれに従う** |
| `resolvesBy` | 承認した側の「こうなれば決着する」という見立て |

## 2. 選択肢を作る

`findings[].ask` が「何を聞くか」を決めている。**AI の仕事は選択肢を作るところだけ。**

選択肢は `source` と、**その行の周辺を実際に読んで**作る。

```bash
# 原文の周辺を読む。前後の節に既に答えが書いてあることがある
sed -n '<line-10>,<line+10>p' <file>
```

- **2〜4 個**。それぞれ「採るとどうなるか」を 1〜2 行（`rules/core.md` §2-3）
- **粒度の違う案を並べる**。「2 種で閉じる／3 種に増やす／4 種に増やす」のように、
  本人が範囲を選べる形にする。中身が同じ言い換えを 2 つ並べない
- **「この記述ごと落とす」を 1 つ入れる**。列挙を閉じる正当なやり方の 1 つで、
  実測でもこれが選ばれた箇所がある
- 本人は自由記述でも答えられる（`Other`）。無理に 4 つ埋めない

## 3. 聞く

`AskUserQuestion` を使う。**1 回に 4 問まで、1 問あたり選択肢 2〜4 個。**

- `header` は group の `header` をそのまま
- `question` は **`source` を逐語で 12 文字以上含める**。含めないと次の記録が拒否される。
  機械側の理由は `rules/core.md` §2「矛盾は逐語引用する」と同じ——
  原文を見せずに聞くと、本人は何について答えているのか分からない

## 4. **その場で**記録する

1 問答えが返るごとに実行する。

```bash
node .claude/scripts/ledger.mjs ask-record "<edge>" "<key>" \
  --question "<実際に聞いた文>" --answer "<決まった中身>"
```

`--answer` には**選んだ選択肢のラベルではなく、決まった中身**を書く。
「3 種」ではなく「アコースティックギター／クリーンエレキ／歪みエレキの 3 種」。
あとで要件定義書に書き写すのはこの文なので、ラベルだけだと意味が復元できない。

### 拒否されたら

```
答えに「など」が入っています。**閉じたつもりで閉じていません。**
```

**実測で 2 回これが起きた。** 本人の答えのほうに「DADGAD や FAG…など」「アーティスト名なども」と
入っていた。**閉じるための質問の答えが閉じていない。** その場でもう一度聞く——
中身を全部挙げてもらうか、「これ以外は対象外」と言い切ってもらうか。

## 5. 残りを確認する

```bash
node .claude/scripts/ledger.mjs ask-report "<edge>"
```

3 つに分かれて出る。

| | 意味 |
|---|---|
| まだ聞いていない | 1 へ戻る |
| 答えを記録した | 聞けたが、**要件定義書はまだ直っていない** |
| 原文を直した | 完了 |

「原文を直した」は**申告ではなく、原文がまだ在るかどうか**で決まる。`key` は原文の本文ハッシュなので、
直せば自動で移る。**移らなければ直っていない。**

---

## 終わったあと

`ask-report` に「答えを記録した」が並んでいる状態がゴール。そこから先は要件定義書の編集で、
**別の指示として出す**（このコマンドは `docs/` に手を入れない）。

編集したら分母を作り直すところまでがセット:

```bash
node .claude/scripts/split.mjs --all
node .claude/scripts/split.mjs drift
node .claude/scripts/ledger.mjs sync "<edge>"
node .claude/scripts/ledger.mjs stale "<edge>"
```
